# 1.2 Changing Requirements, Changing Platforms

These days issues that programmers encounter a different from the problems programmers were solving some odd 40 years ago. Programmers in the 80's knew how the computers worked and had to process large amounts of raw data. These were/are the computer professionals.
Currently there are more 'consumers' of these computers who have little to no knowledge about how computers actually work, one could state the following: A computer is a tool to solve daily 'problems'. I would like to struggle with the computer and actually know how programs work to the core. This will help me with understanding and mastering several aspects:

    - Hardware (Computer and/or devices and their components)
    - Software Programs
    - Hierarchy
    - Networking
    - Application
    - Architecture
    - Bits and Bytes

Availability of these programs for 'users' is made very easy, however the expectations are pretty steep. Some odd 40 years ago a computer took a significant amount of space which we can find in a SBC (Single Board Computer: Raspberry Pi Zero 2W) and it's capacities are way more powerful. The programming requirements change, languages and techniques alike evolve to help professional programmers to manage their complexity. We'll briefly focus on the history of the evolution: the
transformation from procedural programming to object-oriented programming (OOP).

This knowledge I can apply to learn more about cybersecurity and how to find vulnerabilities and reverse engineering. But defending is not the only perspective I'd like to 'master', it is beneficial to learn how to test these programs and devices alike to get the 'whole' picture.
